# 3. Роли и права

Статус: черновик на согласование.

## Два независимых мира

| | Сотрудники компании | Клиенты |
|---|---|---|
| Где работают | Веб-админка (Filament) | Мобильное приложение (и позже веб-кабинет) |
| Таблица | `staff_users` | `users` |
| Вход | Почта + пароль + **второй фактор** (код из приложения-аутентификатора) | Телефон + SMS-код или почта + пароль |
| API | Админка на сервере, наружу API нет | `/api/client/v1/...` |

Клиентский токен не даёт доступа к админке, и наоборот.

## Роли сотрудников

Одному сотруднику можно дать несколько ролей. Каждому сотруднику также задаются **регионы**: он видит заказы, клиентов и закупки только своих регионов. Роль «Администратор» и «Руководитель» могут иметь доступ ко всем регионам.

| Роль | Кто это | Коротко |
|---|---|---|
| Администратор | Технический администратор | Пользователи, роли, настройки, интеграции. Деньги не трогает |
| Руководитель | Руководство | Видит всё в своих регионах, утверждает низкую маржу, отсрочки, возвраты |
| Менеджер | Продажи | Клиенты, заказы, предложения |
| Закупщик | Закупки (О-16) | Поставщики, закупки, распределение |
| Бухгалтер | Бухгалтерия | Счета, выписки, привязка платежей, возвраты |
| Логист | Логистика | Отправления, самовывоз, перевозчики |
| Юрист | Юрист компании | Шаблоны документов, утверждение реквизитов |

## Защита данных

- Закупочные цены и маржа **не попадают** в клиентский API: у клиентского API собственные ответы, и в них этих полей нет.
- Пароли хранятся только в виде хешей. Ключи интеграций — в переменных окружения сервера, не в базе и не в приложении.
- Все действия сотрудников пишутся в журнал.
- Персональные данные: доступ по ролям, хранение в РФ, согласие клиента с версией текста.
