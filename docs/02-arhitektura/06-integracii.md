# 6. Интеграции

Статус: черновик. Каждая внешняя система подключается через **общий интерфейс** (контракт) и отдельный модуль-адаптер. Ядро системы знает только интерфейс.

## Общие правила для всех интеграций

- Ключи и пароли — только в переменных окружения сервера.
- Все обращения — через очередь с повторами (1 мин → 5 мин → 30 мин → 2 ч), потом — уведомление сотруднику.
- Каждое обращение пишется в `integration_logs` (без секретов).
- Пока интеграция не подключена, работает **ручной режим**: сотрудник делает действие сам, с отметкой в журнале. Имитации («фейкового» подписания, оплаты, отправления) нет.

## Банк: как платёж привязывается к счёту

1. Поступление попадает в `bank_transactions` (из файла выписки или API). Повторно загруженный платёж отбрасывается по `external_id`.
2. Система ищет счёт:
   - номер счёта в назначении платежа (`СЧ-SMR-2026-000123` и варианты написания);
   - ИНН плательщика совпадает с ИНН организации счёта;
   - сумма ≤ остатку к оплате по счёту.
3. Все три совпали → привязка автоматически (`method = auto`).
4. Не совпал хотя бы один → платёж в очереди «Неразобранные» у бухгалтера; бухгалтер привязывает вручную с пометкой.
5. Статус оплаты заказа пересчитывается после каждой привязки или её отмены.

## Доставка: выбор способа при оформлении

1. По составу заказа считаются: общий вес (через теоретическую массу), максимальная длина, наличие негабарита.
2. Каждый модуль отвечает `supports()`: подходит ли груз. СДЭК отсекается по весу и длине (лимиты уточняются по договору), для негабарита остаётся доставка компании и самовывоз.
3. Подходящие модули считают стоимость. Цена API показывается с пометкой «расчётная» до создания заявки. Ошибка API → вариант не показывается, клиент видит «стоимость доставки рассчитает менеджер».
4. На этапе MVP итоговую стоимость доставки утверждает менеджер в предложении.

## ЭДО (этап 5)

1. Документ `awaiting_review` → сотрудник проверил → `EdoProvider.send()`; сохраняется ID у оператора.
2. Статусы забираются по расписанию (или по уведомлениям оператора, если есть) → `signatures`, статус документа.
3. Клиент без ЭДО → бумажный путь: письмо с PDF «на подпись» → скан → оригинал. Сотрудник отмечает каждый шаг с файлом.
